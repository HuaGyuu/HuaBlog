# 常见面试题

## IOC

ioc 也就是控制反转，是将对象的创建可依赖关系管理的控制权交给 spring 容器控制

注册 Bean 的几种方式：
1. `@Component`：默认扫描启动类所在包及其子包下的类。通过 `@ComponentScan` 注解，自定义扫描包
2. `@Bean`：通过方法来注册 bean，默认 bean 名称就是方法名
3. `@Import`：导入普通类或配置类
4. 实现 FactoryBean 接口
5. `@Lazy`：懒加载，使用时才创建实例
6. `@Conditional`：在一定条件下才注册 bean
7. `@Profile`：`@Conditional` 的一种实现，在这种环境下，才创建 bean

### Bean 的生命周期

Bean 的生命周期分为五个阶段：
1. **实例化**。Spring 容器会根据 BeanDefinition，通过反射调⽤ Bean 的构造⽅法创建对象实例
2. **属性赋值**。这个阶段 Spring 会给 Bean 的属性赋值，包括通过 @Autowired 、 @Resource 这些注解注
⼊的依赖对象，以及通过 @Value 注⼊的配置值
3. **初始化**。这个阶段会依次执行
    - @PostConstruct 标注的⽅法
    - InitializingBean 接⼝的 afterPropertiesSet ⽅法
    - 通过 @Bean 的 initMethod 指定的初始化⽅法
4. **使用**
5. **销毁**。当容器关闭或 Bean 被移出时，会依次执行
    - @PreDestroy 标注的⽅法
    - DisposableBean 接⼝的 destroy ⽅法
    - 通过 @Bean 的 destroyMethod 指定的销毁⽅法

::: tip 提示
BeanDefinition 是 Spring IoC 容器中描述 Bean 如何创建和配置的元数据对象，包含类名、作用域、依赖、构造参数、属性值、初始化/销毁方法、工厂方法等信息。容器先注册 BeanDefinition，再由 BeanFactory 根据它实例化、注入、初始化成 Bea
:::

### 循环依赖

如果 A 有 B 属性，B 有 A 属性，这就是循环依赖。依赖注入时，并不能简单注入原始，有时候需要注入代理对象。循环依赖的解决方案是**三级缓存**

| 缓存级别     | 名称                      | 存储内容         | 作用                                                         |
| -------- | ----------------------- | ------------ | ---------------------------------------------------------- |
| **一级缓存** | `singletonObjects`      | **完整的 Bean** | 存放已经初始化完成、属性注入完毕、可用的单例 Bean。                               |
| **二级缓存** | `earlySingletonObjects` | **早期的 Bean** | 存放已经实例化（调用了构造函数），但尚未进行属性注入的 Bean。用于解决循环依赖。                 |
| **三级缓存** | `singletonFactories`    | **Bean 工厂**  | 存放用于创建 Bean 的 ObjectFactory。主要用于在循环依赖发生时，提前执行 AOP 代理对象的创建。 |

例如，A 有 B 属性，B 有 A 属性。这时候实例化 A
1. 调用 A 的构造方法，创建 A 的实例。
2. 将 A 的对象工厂放入三级缓存
3. 开始对 A 进行属性注入，发现 A 需要 B，于是开始实例化 B
4. 调用 B 的构造方法，创建 B 
5. 将 B 的对象⼯⼚放⼊三级缓存
6. 开始进⾏ B 的属性注⼊，发现 B 需要 A，于是从一级缓存到三级缓存依次找 A，最终在三级缓存中找到了 A 的对象工厂
7. 调用对象工厂的工厂方法，获得 A 的实例（可能是代理对象，也可能是原始对象），将 A 的实例加入到二级缓存中，并从三级缓存中移出
8. B 拿到 A 的引用，完成属性注入。
9. B 完成初始化等逻辑，将 B 的对象⼯⼚从三级缓存中移出，并将 B 的引用放入一级缓存
10. A 拿到 B 的实例，完成属性注入，并执行后续初始化等操作，最终放入一级缓存

## AOP

AOP，也就是面向切面编程，是把⼀些业务逻辑中的相同代码抽取到⼀个独⽴的模块中，底层是动态代理

AOP 常用于日志，缓存，事务


## 事务

声明式事务底层是使用 AOP 实现。

事务失效的场景：
1. 捕获异常，导致事务不能正常回滚。可以捕获后再抛出异常
2. 抛出检查型异常。spring 默认只会回滚非检查型异常。可以在注解中添加参数：`@Transactional(rollbackFor=Exception.class)`
3. 方法不是 public。
4. 同类内方法自调用。由于事务基于 AOP，而 AOP 基于动态代理，动态代理要创建代理对象，同类中调用方法默认是 `this.xxx()`，也就是直接通过当前对象调用，不经过代理对象。

对于同类方法自调用，有两种解决方案：第一种，注入代理对象：
```java
@Service
public class UserService {

    @Autowired
    @Lazy  // Spring Boot 2.6+ 默认禁止循环依赖，加 @Lazy 避免启动报错
    private UserService self;

    public void methodA() {
        // 通过代理对象调用，事务生效 ✅
        self.methodB();
    }

    @Transactional
    public void methodB() {
        // 数据库操作
    }
}
```

第二种，通过 AopContext 获取代理对象。先要在配置类上暴露代理 `@EnableAspectJAutoProxy(exposeProxy = true)`，然后获取代理对象
```java
@Service
public class UserService {

    public void methodA() {
        // 获取当前对象的代理对象
        UserService proxy = (UserService) AopContext.currentProxy();
        proxy.methodB();  // 事务生效 ✅
    }

    @Transactional
    public void methodB() {
        // 数据库操作
    }
}
```

## Spring MVC 执行流程

1. 请求到达 DispatcherServlet
2. DispatcherServlet 调用 HandlerMapping，根据请求 URL、方法等返回对应的 HandlerExecutionChain（包含 Handler（Controller 方法） 和 拦截器链）
3. DispatcherServlet 根据 Handler 类型，找到能执行它的 HandlerAdapter
4. 调用拦截器链的 preHandle
5. 调用真正的 Controller 方法
6. controller 返回结果
    - 传统 MVC：返回 ModelAndView，包含逻辑视图名和模型数据。
    - 前后端分离：方法加 @ResponseBody，返回对象，由 HttpMessageConverter 直接转成 JSON 写入响应，不再走视图解析。
